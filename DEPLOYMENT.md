# Deploying DocAssist to Google Cloud (fresh project)

Everything runs in **Mumbai (`asia-south1`)**:

| Piece | Service |
|---|---|
| API (Node/Express) | Cloud Run service `docassist-api` |
| Database | Cloud SQL, Postgres 16, `db-f1-micro`, daily backups + point-in-time recovery |
| Logos and signatures | Private Cloud Storage bucket, served through the API at `/uploads/<file>` |
| Secrets | Secret Manager (DB URL, JWT secret, admin password, optional OpenAI key) |
| CI/CD | GitHub Actions with Workload Identity Federation (no service-account JSON keys) |
| One-off tasks | Cloud Run jobs from the same image: migrations, medicine import, admin creation |

No credentials live in the repo. Passwords are generated by the setup script and stored only in Secret Manager.

## 1. Create the project

In the Cloud Console create a new project (e.g. `docassist-prod`) and link a billing account. Then, on your machine with the gcloud CLI:

```bash
gcloud auth login
```

## 2. Run the one-time setup

From the repo root:

```bash
PROJECT_ID=docassist-prod \
GITHUB_REPO=Thirumal255/DocAssist \
ADMIN_EMAIL=you@yourclinic.in \
./deploy/setup-gcp.sh
```

To enable AI suggestions from the start, also pass `OPENAI_API_KEY=sk-...`. Without it, all database-based suggestions and safety checks still work.

Cloud SQL creation takes 5 to 10 minutes. The script is safe to re-run; it skips anything that already exists. Optional overrides: `REGION`, `SQL_TIER` (e.g. `db-g1-small` when you have several clinics), `BUCKET`.

At the end it prints `gh variable set ...` commands. Run them, or add the same values under GitHub → **Settings → Secrets and variables → Actions → Variables**.

## 3. First deploy

Push to `main`, or run **Actions → Deploy backend → Run workflow** with task `deploy`. The workflow:

1. type-checks and confirms the migrations match `schema.prisma` (fails the run on drift),
2. builds the image and pushes it to Artifact Registry,
3. runs `prisma migrate deploy` as the `docassist-migrate` job,
4. deploys `docassist-api` and checks `/health/ready` (API + database).

The run log prints the API URL.

## 4. Load data and create the admin (first time only)

Run **Deploy backend** again with task `bootstrap`. It imports the ~2.5 lakh medicines (a few minutes, safe to re-run) and creates the admin account for `ADMIN_EMAIL`. Get the admin password with:

```bash
gcloud secrets versions access latest --secret=docassist-admin-password --project docassist-prod
```

Log in, change it from the app, and add doctors and receptionists from the admin screens. Do **not** run `prisma/seed.ts` in production: it creates demo accounts with known passwords (it now refuses to run when `NODE_ENV=production`).

## 5. Point the mobile app at the API

The API URL comes from an EAS environment variable, not from code:

```bash
cd mobile
eas env:create --name EXPO_PUBLIC_API_URL --value "https://<cloud-run-url>/api" --environment preview --visibility plaintext
eas build -p android --profile preview      # APK for testing
```

Use `--environment production` with `--profile production` for Play Store builds.

### Automatic APK builds

`.github/workflows/mobile-build.yml` queues an EAS `preview` APK build on every push to `main` that changes `mobile/**`. The run summary links to the build on expo.dev; download and install the APK from there. One-time setup:

1. Create an access token at expo.dev → Account settings → Access tokens.
2. Add it as a GitHub repository **secret** named `EXPO_TOKEN` (`gh secret set EXPO_TOKEN --repo Thirumal255/DocAssist`).
3. Make sure `EXPO_PUBLIC_API_URL` exists for the `preview` environment (above).

For a Play Store bundle, run **Actions → Build mobile app → Run workflow** with profile `production`. Each build counts towards your EAS plan's monthly build limit.

## Day to day

- **Deploy:** merge to `main`. Backend changes deploy to Cloud Run; mobile changes start a new APK build. Schema changes ship as Prisma migrations: run `npx prisma migrate dev --name <change>` locally and commit the new folder. Never use `prisma db push` against shared databases.
- **Logs:** Cloud Console → Cloud Run → `docassist-api` → Logs.
- **Connect to the database:** use the Cloud SQL Auth Proxy (`cloud-sql-proxy <connection-name>`), then `psql`. The instance accepts no direct connections.
- **Rotate the JWT secret:** add a new version of `docassist-jwt-secret`, then redeploy. Everyone is signed out.
- **Turn AI on later:** create the `docassist-openai-api-key` secret (see the setup script output) and redeploy.
- **Restore:** Cloud SQL → `docassist-db` → Backups (daily, plus point-in-time recovery).

## Capacity notes

`db-f1-micro` is a shared-core tier meant for a pilot with one or a few clinics. The API runs at most 3 instances with 5 database connections each, which stays under the tier's connection limit. When you move to a bigger tier, raise `--max-instances` in the workflow together with it. Check current prices in the Google Cloud pricing calculator before choosing a tier.
